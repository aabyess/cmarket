## 1. 심각도별 문제 목록

### 1.1 치명적 (Critical)

**C1. 모바일에서 로그인 후 전체 서비스 내비게이션 불가**
- 위치: `components/layout/Sidebar.tsx:70` (`hidden lg:flex`) + `app/(main)/layout.tsx:12-19`, `app/admin/layout.tsx:25`
- 문제: 사이드바가 1024px 미만에서 완전히 사라지는데, 모바일 대체 내비게이션(햄버거 메뉴/하단 탭바)이 어디에도 없음.
- 왜 문제: 모바일 브라우저로 로그인하면 대시보드 외 어떤 화면으로도 이동할 방법이 없음(주소창 직접 입력 제외). B2B 서비스라도 실사용자가 모바일로 접속하는 순간 서비스 이용이 사실상 불가능. 관리자 화면도 동일 문제.
- 개선 방향: 모바일 브레이크포인트용 햄버거 메뉴 또는 하단 탭바 추가.

**C2. Toast 시스템 부재로 인한 `alert()` 전역 남용 (40여 곳)**
- 위치(대표): `ContractList/index.tsx:65,91,105` / `ListingDetailActions.tsx:26` / `PostListingForm/index.tsx` 5곳 / `ListingDescriptionEditor.tsx` 2곳 / `ListingAttachmentSection.tsx` 3곳 / `QuoteReview/index.tsx:65,69` / `SignupInfoKorea.tsx:292` / `SignupInfoIndonesia.tsx:330` / `SiteBuilderFields.tsx:155,212` / `ListingInfoAttachments.tsx:32`
- 문제: 프로젝트 전체에 `toast`/`Toaster` 계열 컴포넌트가 전혀 없음(전체 검색 0건). 성공/실패 피드백을 브라우저 네이티브 `alert()`로 처리.
- 왜 문제: 네이티브 alert는 스타일링 불가, 확인을 눌러야 다음 동작이 가능해 폼 작성 흐름을 강제로 끊음, 앱 톤과 괴리. 반대로 성공 시엔 무피드백인 곳도 많아 성공/실패 피드백 방식 자체가 화면마다 다름.
- 개선 방향: 공용 Toast 컴포넌트 도입 후 전체 `alert()` 교체.

**C3. Primary 브랜드 컬러 이원화 (`#3B82F6` 하드코딩 vs `#2563EB` 토큰)**
- 근거: `app/globals.css:74,111` 주석에 `#3B82F6 → #2563EB` 리브랜딩 이력이 명시돼 있음에도, `PostListingForm` 전체, `SignupInfoKorea/Indonesia.tsx`, `ContractList/index.tsx`, `MyQuotesCard.tsx`, `SiteRenderer*` 6개 파일, `ListingBrowse`, `ListingDetailQuoteForm.tsx`(seller), Admin 다수 화면이 여전히 구 색상(`#3B82F6`)을 하드코딩.
- 왜 문제: 같은 앱 안에서 "브랜드 파랑"이 두 가지 톤으로 보임. 토큰을 바꿔도 절반만 반영되는 구조.
- 개선 방향: 하드코딩된 `#3B82F6`을 전부 `text-imsg-blue`/`bg-imsg-blue` 등 토큰으로 일괄 치환.

**C4. 파괴적 액션(삭제)의 확인 절차 불일치**
- 위치: `SiteBuilderBlockCard.tsx:91-98`(블록 삭제, 확인 모달 없음) / `AdminResources/index.tsx:57-65`(자료 삭제, 확인 모달 없음)
- 참고(모범 사례): `AdminNoticeForm`은 같은 화면군인데 `ConfirmModal`을 정상적으로 사용 중.
- 왜 문제: 되돌릴 수 없는 삭제가 클릭 한 번에 즉시 실행됨. 프로젝트에 이미 `components/ui/confirm-modal.tsx`가 있는데도 화면마다 쓰고 안 쓰고가 갈림.
- 개선 방향: 모든 삭제 액션에 기존 `ConfirmModal` 일괄 적용.

**C5. 알림 삭제 버튼이 hover 상태에서만 노출됨**
- 위치: `features/notifications/components/NotificationBell/index.tsx:164-169` (`opacity-0 group-hover:opacity-100`, `group-focus-within` 없음)
- 왜 문제: 터치 기기(모바일)는 hover 자체가 없고, 키보드로 Tab 이동해도 보이지 않아 삭제 기능에 물리적으로 접근 불가.
- 개선 방향: `group-focus-within:opacity-100` 추가 또는 상시 노출.

**C6. 하드코딩된 안내 문구와 실제 동작 불일치**
- 위치: `features/auth/components/SignupComplete/index.tsx:31-35` — "n초 후 대시보드로 이동합니다" 표기하지만 실제론 `/login`으로 이동
- 위치: `app/(auth)/login/page.tsx:56` — `alt="SantaraPay 로고"`인데 실제 이미지는 `MitraPay.png`, `SignupComplete`는 "MitraPay"로 표기 → 브랜드명이 SantaraPay/MitraPay 두 가지로 혼용
- 왜 문제: 사용자에게 잘못된 기대를 심어주고 브랜드 신뢰도를 떨어뜨림.
- 개선 방향: 안내 문구를 실제 라우팅에 맞게, `alt`/브랜드 표기를 실제 서비스명으로 통일.

**C7. 죽은 코드가 실제 컴포넌트와 다른 팔레트를 유지한 채 방치됨**
- 위치: `DashboardHome`(buyer)의 서브컴포넌트 6개(`ActivityFeed`,`NextTodos`,`QuickMenu`,`SavingsCard`,`TodoCard`,`Waiting`) — 미사용, 하드코딩 hex
- 위치: `QuoteCompareTable.tsx`, `QuoteReviewCard.tsx`(buyer QuoteReview) — 미사용, `ConfirmModal` variant도 실사용 컴포넌트(`default`)와 다름(`danger`)

- 개선 방향: 미사용 확인 후 삭제, 필요 시 실사용 컴포넌트에 로직만 병합.

**C8. 클릭해도 반응 없는 버튼(Dead click)**
- 위치: `Sidebar.tsx:115,123,131` — 프로필 드롭다운 "환경설정/이용약관/개인정보처리방침" `href="#"`

### 1.2 중요 (Important) — 주제별 통합

**I1. 색상 대비 미달 가능성 (WCAG AA 기준 4.5:1 미만)**
- `app/globals.css:114` `--imsg-secondary: #8e8e93` (흰 배경 대비 약 3.26:1) — seller 라벨/보조정보 전반(`ListingBrowseCard`, `MyQuotesCard/Table`, `ListingDetailInfo` 등)에 광범위 사용
- 회원가입 폼 placeholder `#9CA3AF` (추정 대비 ~2.8:1) — `SignupInfoKorea/Indonesia.tsx`
- 개선 방향: 토큰 명도를 낮춰 4.5:1 이상 확보, 또는 본문성 텍스트용 별도 토큰 분리.

**I2. `focus-visible` 스타일 전역 부재**
- `app/globals.css` 전체에 `focus-visible` 관련 정의 0건. Seller 전 버튼/탭/폼(`ListingBrowse`,`MyQuotesFilterBar`,`ListingDetailQuoteForm` 등)에서 확인, 다른 영역도 동일 패턴으로 추정.

- 개선 방향: 공통 버튼/인터랙티브 요소 base 스타일에 `focus-visible:ring-2` 류 규칙을 디자인 시스템 레벨로 강제.

**I3. 아이콘 전용 버튼에 `aria-label` 부재 (반복 패턴)**
- `components/commons/Pagination/index.tsx:40-69`(4개 버튼) / `NotificationBell:103-105`(벨) / `Sidebar.tsx:75-86`(드롭다운 트리거) / `SiteBuilderBlockEditor.tsx`·`SiteBuilderFields.tsx`(삭제 버튼 다수) / `ListingBasicSection.tsx:120-126`(품목 삭제 "×") / `ListingAttachmentSection.tsx:139-144`(X 아이콘) / `login/page.tsx:90-95`(비밀번호 표시 토글)
- 개선 방향: 아이콘 전용 인터랙티브 요소에 `aria-label` 부여를 컴포넌트 컨벤션으로 정착.

**I4. 드롭다운/탭에 ARIA 시맨틱 및 Esc 닫기 부재**
- `Sidebar.tsx:99-149`, `NotificationBell:112-175` — 드롭다운 2곳 모두 바깥 클릭으로만 닫히고 Esc 미지원, `aria-haspopup`/`aria-expanded` 없음
- `ContractListTabs.tsx:44-56` — `role="tablist"/"tab"`, `aria-selected` 없음, 방향키 전환 미지원
- 개선 방향: 공통 드롭다운/탭 패턴에 role/aria/Esc 핸들러 표준화.

**I5. `--color-success`/`--color-warning` 토큰이 `@theme inline`에 미등록**

## 3. 전체 요약 — Top 5

가장 먼저 손대야 할 5가지, 우선순위 순:

1. **모바일 내비게이션 부재 해결** (C1) — 로그인 후 서비스 전체가 1024px 미만에서 사용 불가능한 상태입니다. 실사용자 이탈로 직결되는 가장 심각한 문제이며, 다른 어떤 개선보다 비즈니스 영향이 큽니다.
2. **Toast 컴포넌트 도입 후 `alert()` 전면 교체** (C2) — 40여 곳에서 브라우저 네이티브 alert가 UX 흐름을 끊고 있습니다. 하나의 공용 컴포넌트만 만들면 전 영역에 걸쳐 즉시 체감 개선이 됩니다.
3. **Primary 컬러 토큰 통일** (C3) — 리브랜딩(`#3B82F6→#2563EB`)이 절반만 반영돼 앱 전체가 두 가지 파랑으로 보입니다. 디자인 토큰 준수 여부를 점검하는 린트 규칙(예: hex 리터럴 금지) 도입까지 고려할 만합니다.
4. **삭제 등 파괴적 액션에 확인 모달 일괄 적용** (C4) — 이미 만들어진 `ConfirmModal`을 SiteBuilder/Admin 삭제 액션에 연결하기만 하면 되는, 비용 대비 효과가 가장 큰 수정입니다.
5. **키보드/스크린리더 접근성 기반 정비** (C5, I2, I3, I4) — `focus-visible` 전역 스타일, 아이콘 버튼 `aria-label`, 드롭다운 ARIA/Esc 처리를 공통 컴포넌트 레벨에서 표준화하면 개별 화면을 하나씩 고치는 것보다 훨씬 적은 노력으로 전역 문제가 해결됩니다.

이 5가지는 모두 "공용 컴포넌트/토큰 레벨"에서 해결 가능한 구조적 문제로, 화면별로 하나씩 고치는 대신 디자인 시스템 레이어에서 먼저 정리하면 파급 효과가 가장 큽니다.
